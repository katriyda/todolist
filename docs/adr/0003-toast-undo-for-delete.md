# ADR-0003: 使用 Toast + 撤销替代确认对话框

## 状态

已接受

## 上下文

删除操作需要防止误操作。传统方案是使用 `confirm()` 对话框，但体验不佳。

## 决策

使用 toast 提示 + 撤销按钮（5 秒后自动删除）替代确认对话框。

### 理由

1. **现代 UI 趋势**：Gmail、iOS 等主流应用都采用此模式
2. **不阻塞操作**：用户可以继续操作，无需立即决定
3. **减少焦虑**：给用户反悔的机会，降低误操作的心理负担
4. **移动端友好**：原生 `confirm()` 在移动端体验差

### 替代方案

- **原生 confirm()**：阻塞主线程，样式不可控
- **自定义模态对话框**：仍然阻塞操作流程
- **二次确认按钮**：增加操作步骤，体验繁琐

## 后果

- 需要实现 toast 组件和 5 秒定时器
- 需要维护 undo stack 支持撤销
- 删除操作有 5 秒延迟，需要在 UI 上明确提示
