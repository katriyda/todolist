# ADR-0004: 极简单列布局 UI 设计

## 状态

已接受

## 上下文

需要为 Todo 应用选择 UI 设计方案。生成了三个方案：
1. 极简单列布局（最大留白，排版驱动）
2. 高密度仪表盘（侧边栏统计，信息密集）
3. 看板三列布局（按状态分列，拖拽友好）

## 决策

采用**方案 1（极简单列布局）**，借鉴方案 3 的卡片样式元素。

### 理由

1. **应用场景匹配**：个人 Todo 应用，非团队项目管理工具，不需要看板的复杂状态
2. **移动优先**：单列布局在移动端体验最好，无需折叠侧边栏或多列堆叠
3. **CSS 复杂度低**：符合项目"原生 CSS、无依赖"的约束，样式代码量最少
4. **认知负荷最低**：排版驱动层级，用户视线单一方向（向下），扫描效率最高
5. **性能最优**：无阴影、无渐变、无模糊，绘制成本最低

### 替代方案

- **方案 2（仪表盘）**：信息密度高，但认知负荷大，移动端需折叠侧边栏
- **方案 3（看板）**：状态分离清晰，但水平空间紧张，状态模型复杂（3 状态）

### 借鉴元素

从方案 3 借鉴：
- 桌面端可为 todo item 添加微妙的卡片效果（可选）
- 标签 pill 样式

## 后果

- 只支持 2 种状态（active/completed），不支持 "in_progress"
- 不适合拖拽排序场景（单列拖拽体验差）
- 信息密度较低，50+ todo 需要滚动或虚拟列表
- 操作可发现性依赖 hover（桌面端），移动端需长按或滑动
