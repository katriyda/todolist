# ADR-0002: localStorage 持久化 + 300ms 防抖

## 状态

已接受

## 上下文

Todo 数据需要在页面刷新后保留。需要选择持久化方案和保存时机。

## 决策

使用 localStorage 持久化，状态变更时 300ms 防抖保存。

### 理由

1. **无后端依赖**：纯前端应用，localStorage 是最简单的持久化方案
2. **防抖保存**：避免频繁写入（如批量删除），平衡响应性和性能
3. **300ms 延迟**：足够短以保证用户感知的即时性，足够长以合并连续操作

### 替代方案

- **立即保存**：频繁写入可能影响性能
- **IndexedDB**：对于简单列表过于复杂
- **后端 API**：增加服务器依赖和网络延迟

## 后果

- 数据存储在浏览器中，清除浏览器数据会丢失 todo
- localStorage 有容量限制（~5MB），超过 1000 个 todo 需要考虑虚拟列表
- 需要处理 localStorage 错误（容量超限、隐私模式）
